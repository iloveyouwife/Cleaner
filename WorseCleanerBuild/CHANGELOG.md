## Cleaner v0.91.0 — 稳定性与恢复能力改进

- 保留 v90 首页、搜索、键盘、滚动动画、字体、图标、间距和高级设置布局；只完善已有排除管理的数据来源，暂未发现的旧记录仍可使用原有按钮恢复。
- 正式版本在源码检查、Release 编译、全部逻辑测试和 UI 回归通过后才发布。每条 xcodebuild 命令只执行一次 test，搜索专项与完整 UI 套件不再重复覆盖同两项测试；过期 main 提交不发布为 latest。
- App 名称归属必须有 MCM、元数据或精确 LaunchServices 容器路径证据；单个偏好文件、SDK 配置或另一个已安装 App 的名称不再单独确认归属，冲突时保留未知身份。
- 手动添加支持已发现的 UUID，或能够只读验证且唯一对应 App/扩展根目录的 UUID。无法唯一确认时要求完整路径；不猜测容器类型、不扩大白名单。
- 专用 App Group 暂存增加先写事务记录、原目录与父目录 inode/device 核验。后续已授权请求前可恢复已验证的中断事务；来源不明的旧版备份、损坏记录、被替换的目录或路径冲突仍保留数据并停止授权，诊断会说明原因。
- 同次发现和扫描可复用未变化的 LaunchServices 解析结果；组、路径或文件状态变化以及状态未知均使其失效。缓存计量和删除授权仍逐次执行。动态库函数表只加载一次，减少重复名称查询。
- 清理结果明确为“缓存逻辑大小减少约”，不将文件逻辑大小差承诺为设备即时释放空间。保留成功删除计数及清理后复核规则，补充具体清理失败原因到原有诊断日志。
- 增加六套 CSStore2 布局的合成二进制样本测试，以及冲突、截断、非法引用、名称安全、解析复用失效、归属证据、UUID、旧排除记录、暂存中断与数据保留测试；原搜索 UI 回归继续作为必需检查。
- 增加 v90 受保护界面文件的哈希检查；历史记录移至 CHANGELOG.md，更新过时技术说明，移除无调用的单根 pathleak 包装。

保留 [v0.90.0](https://github.com/iloveyouwife/Cleaner/releases/tag/v0.90.0) 和 [v0.89.0](https://github.com/iloveyouwife/Cleaner/releases/tag/v0.89.0) 的源码与 IPA。

附件为未签名 IPA，安装需使用自己的有效签名和独占 App Group。模拟器通过不代表所有真机、系统版本或签名都具有相同访问能力。旧版无事务记录的遗留备份不会被自动删除或强行覆盖；有冲突时保留原数据并停止操作。

完整历史：[CHANGELOG.md](https://github.com/iloveyouwife/Cleaner/blob/main/WorseCleanerBuild/CHANGELOG.md)。

## Cleaner v0.90.0 — 高级设置入口、专用缓存暂存保护及中断清理统计

- App Group 未确认、不可用或被手动关闭时，**不再自动发现 App、不调用 MCM / LaunchServices / inode 搜索，也不进行缓存扫描**；刷新、深度发现、手动添加和联网名称补全均阻止无效操作。关闭权限时清除界面上此前的缓存大小和 App 列表，不删除用户文件或手动排除记录。重新确认后自动进入原来的发现和扫描流程。
- 修复首页“请确认 App Group”提示下“打开高级设置”点按无响应的问题：未进入搜索编辑状态时，不再启用 List 的额外全局点按/拖拽手势，提示按钮使用原生无边框按钮；搜索激活时原有 160ms 防抖、0.28s 动画、0.12s 滚动显隐以及键盘焦点行为不变。

- 清理 Caches 成功后，若打开 tmp 时出现权限错误，不再丢掉已成功删除项目的统计：停止后续删除，增加失败计数，继续复核已删除数量与空间；复核失败时仍不得猜测已释放字节数。
- **保持 v89 原生整体 UI 布局、按钮位置、图标及字体。** 容器发现、缓存扫描范围、清理白名单（仅 Caches/tmp）、权限请求 class/part/flags、原有描述符路径防护均不扩展。
- 增加 5 项底层边界单元测试及“App Group 未确认时打开高级设置”的专项 UI 回归测试；候选改动经 Xcode 27 编译与独立单元测试，真机仍需按当前 App Group 签名实际验证。
- **v89 稳定回退包保留：** [Cleaner v0.89.0](https://github.com/iloveyouwife/Cleaner/releases/tag/v0.89.0)。不覆盖或删除该版本的源码标签与 IPA。

## Cleaner v0.85.0

### 修复滚动反馈循环：List 高度不再随搜索栏收放变化

- 复查 v82-v84 的根本架构问题：列表 List 的 viewport 会随着上方搜索栏高度变化而增减，导致 contentOffset 的测量结果变化，再反向驱动搜索栏高度；因此即使 v84 只读取真实滚动位移，仍可能出现跳动、第一下滑动无效及搜索栏卡住。
- v85 使用单一 List 滚动容器；在 scrollContent 顶部固定预留 70pt（42pt 搜索胶囊 + 18pt 上边距 + 10pt 下边距）。搜索输入框作为 List 外层固定身份的 overlay 绘制，且保持固定布局高度，仅随实际 contentOffset 向上平移并裁切。此举避免搜索栏高度改变 List viewport 和 offset，切断反馈环路。
- 保留 v84 的滚动位置唯一控制、顶部 Soft scroll edge 模糊、浅灰背景、点击空白/滑动关闭编辑、稳定键盘与 v71 的搜索激活 0.28s 动画和圆形关闭按钮。没有恢复 v77 基于丢失坐标偏好的隐藏逻辑。
- 缩短纯视觉平滑到 0.12s，避免快速往返时明显拖尾。仍保持 160ms 搜索结果防抖。
- UI 回归测试加强：第一次上滑后必须不可点击、第一次下拉就必须恢复，再次上滑不得滞留、第二次下拉恢复；原有键盘及清理安全测试保留。
- 扫描、清理权限、路径白名单、App 名称识别、系统状态、其余页面均未改变。发布 IPA 不代表真机滚动手感已确认；必须以实测结果为准。

### 沿用 v0.53.0 的能力

- 改用设备上的动态 inode 上限，不再固定只扫描前 500 万个 inode。
- 分块并行扫描（最多 6 个工作线程，系统温度升高时自动收缩），重复扫描时验证已有索引并仅检查新增 inode；手动深度发现可触发全量刷新。
- 将 App 扩展的缓存容器纳入发现，并与普通 App 分开标识；仍不扫描内部守护进程或系统数据。
- 对容器根目录可访问、但 `Caches` 或 `tmp` 返回 `EPERM` 的情况，仅对该缓存目录尝试额外的临时访问授权，不扩大可删除路径范围。
- 扫描进度显示当前 inode 百分比；无法访问或无法完整测量的容器继续排除清理。

适用于 iPhone 的 App 缓存扫描与选择性清理实验工具。当前界面使用 SwiftUI、iOS 原生菜单和 SF Symbols，支持搜索、排序、多选、排除管理与访问诊断。

### 安装包

- 附件 `Cleaner-v*-unsigned.ipa` 为**未签名** IPA。
- 安装前需要自己的有效证书、provisioning profile，以及实际授权的独立 App Group。
- 请勿使用其他 App 已共享的 App Group；操作前应自行备份重要数据。

### 清理范围

仅尝试处理已发现、已授权、已扫描且用户明确选中的 App 数据容器内 `Library/Caches` 和 `tmp` 的内容。不会删除 Documents、App 本体或系统数据。

**访问能力不作保证：** iOS 沙盒、签名和系统版本可能阻止第三方 App 容器访问。发布构建成功、模拟器截图测试通过不等于已在所有真机上验证清理效果。本应用不提供 root、越狱或永久签名。
